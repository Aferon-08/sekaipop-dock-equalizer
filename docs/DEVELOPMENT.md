## Проверки без запуска оболочки

Нужны Python 3 и Node.js 22.16+ (используется `import.meta.dirname`).

```sh
python3 -m compileall -q .
python3 build-pet-worker.py --check
node tests/tube-and-family.mjs
node tests/bubble-family.mjs
```

Проверки подтверждают одну геометрию трубы в обоих направлениях, движение головы по физической кривой, изоляцию следа между персонажами/транспортами, криволинейные локальные/пузырьковые маршруты, самостоятельные путешествия близнецов, возврат и слияние только после фактического сближения, а также случай с пластиковой перегородкой. Они не подменяют визуальные проверки на GPU.

Для проверки обновления/repair/install/uninstall на временной копии файлов установленной оболочки:

```sh
python3 tests/installer.py --shell-dir "$HOME/.config/quickshell/sekaipop"
```

Эта проверка использует временные XDG-каталоги и не изменяет реальную установку. Нужен `qs`, поскольку установщик проверяет состояние целевой оболочки.

## WorkerScript

`PetPlannerWorker.mjs` — генерируемый пакет. Правьте исходные `GlassRoutes.js`, `PetPhysics.js`, `PetNavigation.js`, `PetMotion.js` и `BubbleTransfer.js`, затем:

```sh
python3 build-pet-worker.py
python3 build-pet-worker.py --check
```

Расширение `.mjs` важно для изолированного Qt WorkerScript. Сохраните адресацию запросов по generation/request/actor; ответы предыдущей сцены или другого огонька не должны менять текущий маршрут.

## Шейдеры

Нужен `qsb` из Qt Shader Tools, соответствующий целевой версии Qt. Исходные `.frag` включены; `.qsb` поставляются для удобства установки. Например:

```sh
/usr/lib/qt6/bin/qsb --glsl '100 es,120,150' --hlsl 50 --msl 12 \
  -o wallpaper-wire-glow.frag.qsb wallpaper-wire-glow.frag
```

При изменении shader uniform меняйте QML-параметры и пересобирайте QSB вместе. Проверяйте альфа-смешивание, ореол поперёк узкой трубы, след на входе/выходе и отображение под перекрывающими слоями. Логика движения должна использовать ту же физическую кривую, что и изображение трубы.

## Воспроизвести демонстрации

Нужна работающая графическая сессия с Quickshell. Рендерер открывает отдельное тестовое окно, работает с временной копией компонентов и не запускает запись Spotify/модели/штатный сервис оболочки.

```sh
python3 tools/render-demo.py dock /tmp/dock-frames
python3 tools/render-demo.py wallpaper /tmp/wallpaper-frames
python3 tools/render-demo.py voices /tmp/voice-frames
```

PNG-кадры можно собрать FFmpeg: док/голоса — 20 fps, обои — `100/7` fps. Сцены используют тестовые слова и синтетический спектр; раннее разделение питомца специально вызвано сценарием демонстрации. Не измеряйте по ним нагрузку установленного shell.

## Изменять работающую установку

В ветке v3 обновляйте папку плагина через менеджер после завершения аудиозаданий; install.py здесь не устанавливает компоненты. В стабильной ветке v2 для обновления с сохранением данных применяется `python3 install.py --repair`. Проверяйте IPC обоих мониторов и журнал: список плагинов сам по себе доказывает только обнаружение манифеста, но не успешную отрисовку дока.

В первоначальной публикации выполнены: регрессии JS, соответствие worker-пакета, изолированный тест установки и repair, проверка Python, визуальная проверка демонстраций и фактическая загрузка адаптеров на двух мониторах. Универсальный прогон всех моделей на чистой системе в CI не выполняется.
