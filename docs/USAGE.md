# Док, лирика и анализ

[← README](../README.md)

## Музыкальный док

Музыка определяется по MPRIS. Ожидание воспроизведения не требует постоянно открытого аудиопотока. Когда музыка играет, CAVA читает монитор выбранного системного выхода; после паузы аудиопрослушивание визуализатора прекращается, а волна затихает перед складыванием капсул.

Горизонтальный док на пустом рабочем столе раскрывается до музыкальной карточки. При видимом окне используется компактный режим. Наведение возвращает иконки приложений. Поддержка вертикального дока относится к боковым капсулам; расширенный текстовый плеер рассчитан на горизонтальную компоновку.

В раскрытом виде доступны обложка, название и исполнитель, предыдущий/следующий трек, пауза и прогресс, если эти операции предоставляет плеер. Во время паузы карточка остаётся, волнистый прогресс выпрямляется, анимация текста останавливается, центральный огонёк продолжает спокойное движение. При паузе карточку можно потянуть за верхнюю область, чтобы вернуть обычный док до следующего воспроизведения.

Если синхронизированной лирики нет, доступен инструментальный режим. Ожидание между фразами показывает троеточие; в конце каждой партии появляется собственный финал, затем области сходятся в общий. Ближе к концу композиции `The end of lyrics :)` превращается в `The end :)`.

## Два разных световых элемента

- **Точка-маркер** прыгает по словам и следует таймингам. При нескольких голосах быстро расходится по их областям.
- **Огонёк** — мягкий свет со следом, который преследует маркер с задержкой. У него отдельная анимация разделения и объединения, изменение яркости и сердцебиение.

Огонёк не должен заменять собой маркер или уводить точку из синхронизации с текстом.

## Источники лирики и таймингов

Используется лирика, которую получает штатный `LyricsService` SekaiPOP для выбранного трека. Можно импортировать JSON формата Lyrics Wordtime Extractor; данные проверяются перед применением. Обложка открывает окно таймингов, где можно выбрать готовый JSON, подходящий аудиофайл или изменить текст.

Локальное выравнивание требует **готового текста** и той же записи песни: студийная версия и концертная запись могут давать разные тайминги. Это не универсальная автоматическая транскрипция из одного аудио. Полученная разметка кешируется отдельно для записи трека.

## Как запросить анализ

1. Подготовьте основной обработчик; при необходимости — модели голосов и CUDA.
2. Откройте трек. Для Spotify дайте ему проиграться с начала полностью: аудиозапись сохраняется отдельно от запроса генерации.
3. Нажмите значок анализа в правом нижнем углу стеклянной области. Он остаётся спокойным, пока обработка не запрошена. Можно запросить заранее, во время записи.
4. Для повторного расчёта используйте действие **«Перегенерировать»** в окне таймингов.
5. Окно можно закрыть без отмены. Кнопка отмены останавливает задание; имеющаяся запись сохраняется для повторной попытки.

Тяжёлый расчёт общий для всех мониторов. Пока он идёт, прежняя разметка остаётся доступна. Ошибка или отмена не должны заменять готовые тайминги частичным результатом. Прогресс приблизительный: этап анализа голосов может быть заметно дольше выравнивания слов.

YouTube-источник и локальный файл используют ту же ручную заявку. В браузере доступность аудио зависит от URL и источника; при невозможности получить нужную запись выберите локальный файл. Сетевые сервисы и доступность URL могут меняться.

## Голоса и ограничения анализа

Явная разметка партий и времён слов в источнике — лучший вариант. Без неё движок использует дополнительные признаки: выделение вокала, разделение перекрывающихся партий, речевые/певческие представления голосов и сопоставление фраз. Это даёт оценку, а не гарантированную идентификацию исполнителей.

- Неименованные партии подписываются «Голос 1», «Голос 2» и т. д.
- Области удерживаются на протяжении фрагментов, чтобы короткие паузы не переключали всё на первый голос.
- Одновременные одинаковые строки могут объединяться; для нечётного количества областей основой служит центральная, для чётного — левая.
- Короткое дополнение/повтор может отображаться полупрозрачным наклонным бэком над основной строкой. Независимый отличающийся текст не должен автоматически превращаться в подпевку.
- Нынешняя модель разделения ориентирована на **две одновременные партии**. Последовательных ролей может быть больше; визуальная поддержка нескольких областей не означает безошибочного разделения трёх и более одновременно звучащих певцов.
- Если отдельный параллельный текст отсутствует в исходной лирике, его полное достоверное восстановление не гарантируется. Хор, реверберация, смена тембра одного певца и очень плотные миксы могут давать ошибки.

## Настройки

В 2.22.0 доступны [55 параметров в отдельной жидкой панели](SETTINGS.md).

| Группа | Основные параметры |
|---|---|
| Расположение | Включение капсул, длина, высота, отступ. При нехватке места капсулы скрываются. |
| Звук | Волна/столбики, чувствительность. |
| Анимация | Задержка складывания после паузы, по умолчанию 600 мс. |
| Лирика | Подмена иконок, раскрытие на рабочем столе, ширина, многоголосный режим, запись Spotify, CPU-потоки, CPU/NVIDIA. |
| Обои | Включение, движение, плотность, доля стекла, новая композиция, огонёк. |

Точные значения по умолчанию и пределы находятся в [`plugin.json`](../plugin.json). Настройка «Создать новую композицию» — разовое действие и сама возвращается в выключенное состояние.
